Regex rules silently allow 1 in 3 agent attacks.

Pattern rules catch rm -rf and known-bad domains. They can't tell if a normal-looking email or data export was hijacked by poisoned tool output. Voan adds an LLM judge that checks every action against the user's actual goal — and only ever escalates to block.

Rules also hold another 35% of attacks for a human (ASK on money/external sends); the judge turns the silently-allowed 30% and the held cases into blocks. The one false positive is a legitimate DROP TABLE blocked by design — the judge never loosens a hard block. 36 hand-curated cases, one judge run: an optimistic ceiling, not a production guarantee; a real-trace eval is on the roadmap.

How it works

A lightweight in-process sensor, a fast rule brain, an LLM judge for the gray zone — the antivirus model, for agents.

Sensor

One-line in-process hook on every tool call. Zero deps; any Python or JS agent whose tools you wrap — LangChain, OpenAI function-calling, plain callables.

Rules

Fast local regex tier: blocks RCE, exfiltration, destructive DB, credential leaks; holds money for a human. Signature blocklist, default-allow (opt into deny-by-default).

Judge

Opt-in LLM “intent vs. hijack” tier that only ever escalates. Pluggable: local Ollama or OpenAI — sends action + context to the model (secrets auto-redacted; use local for privacy).

Scan, then block.

Voan Firewall is a standalone runtime guard. It will pair with the Voan Scanner (companion, private beta) that finds an agent's holes before you ship — together: find, then block. Open-source, Apache-2.0.
